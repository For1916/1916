# 황소 워크북 장부

판매와 지출로 **황소 워크북**의 이익을 보고, 같은 페이지의 **재고** 탭에서 교재와 포장 박스 수량을 따로 봅니다. 깃허브 페이지의 화면과, 구글 시트 `황소 워크북 장부`에 붙이는 Apps Script 웹 앱으로 이루어져 있습니다.

이익과 재고는 한 스프레드시트, 한 웹 앱, 한 비밀번호를 씁니다. 시트를 둘로 나누면 배포와 비밀번호가 두 벌이 되므로, 재고는 같은 장부 파일 안의 별도 탭으로 두었습니다.

이 장부에는 주문자 이름, 전화번호, 주소, 모아폼 답변 번호, 유입 경로를 저장하거나 보여 주지 않습니다. 판매는 `주문 연동`의 날짜·상태·금액만 사용하고, 상태가 취소 또는 환불인 주문은 뺍니다. 지출 분류는 **제본, AI, 광고, 박스** 네 가지입니다. 재고가 읽는 교재 글자는 `주문 출고` 탭에만 있고, 이익용 `주문 연동`에는 넣지 않습니다.

화면 주소(배포 후): https://for1916.github.io/1916/Workbook_Ledger/

## 파일

| 파일 | 역할 |
| --- | --- |
| `index.html` | 장부 화면. 깃허브 페이지가 이 파일을 엽니다. |
| `apps-script/Code.gs` | 시트에 붙여 넣을 스크립트. 읽기·추가·수정·삭제와 개인정보 열 정리를 합니다. |

## 배포

개발 도구를 쓰지 않아도 됩니다. 아래 순서만 따라 하면 됩니다.

### 1. 스크립트 붙여 넣기

1. 구글 시트 **황소 워크북 장부**를 엽니다.
2. 메뉴 **확장 프로그램 → Apps Script** 를 누릅니다.
3. 편집기에 있는 `Code.gs` 내용을 모두 지우고, 이 폴더의 `apps-script/Code.gs` **전체**를 붙여 넣습니다.
4. 디스켓 아이콘으로 저장합니다.
5. 왼쪽 톱니바퀴 **프로젝트 설정**에서 다음을 확인합니다.
   - 시간대: **(GMT+09:00) 서울**
   - 런타임: **Chrome V8**

### 2. 초기 설정을 한 번 실행

이 단계가 시트에서 개인정보 열을 지웁니다. 이미 지워진 상태에서 다시 실행해도 됩니다.

1. 시트 탭으로 돌아가 **새로고침**합니다.
2. 상단 메뉴에 **황소 장부**가 보이면 **황소 장부 → 초기 설정**을 누릅니다.
3. 비밀번호를 묻는 창이 나오면, 웹 장부에 쓸 비밀번호를 입력하고 확인을 누릅니다. 4자 이상으로 길게 정하세요. 웹 주소는 공개되어도 이 비밀번호 없이는 내용을 볼 수 없습니다.
4. 구글이 권한을 물어보면 본인 계정을 고르고 **허용**을 누릅니다. 시트 주인인 본인 스크립트라서 별도 보안 예외를 켤 필요는 없습니다.

메뉴가 보이지 않으면 Apps Script 편집기에서 함수 목록의 **setup** 을 고르고 실행을 누릅니다. 편집기 실행에서는 비밀번호 창이 뜨지 않을 수 있습니다. 그때는 3번의 스크립트 속성으로 비밀번호를 넣습니다. `setup` 은 비밀번호가 없어도 열 정리는 진행합니다.

`주문 연동` 시트에 `#REF!` 와 함께 **액세스 허용**이 보이면 그 버튼을 누릅니다. 다른 시트의 주문 목록을 다시 가져오는 허락입니다.

### 3. 비밀번호를 스크립트 속성에 두기

메뉴에서 비밀번호를 저장했다면 이 단계는 건너뜁니다. 저장됐는지는 **황소 장부 → 개인정보 열 점검** 에서 `비밀번호: 설정됨` 으로 확인합니다.

직접 넣을 때:

1. Apps Script **프로젝트 설정 → 스크립트 속성 → 스크립트 속성 추가**
2. 속성: `LEDGER_PASSWORD`
3. 값: 사용할 비밀번호
4. 저장

비밀번호는 HTML이나 깃허브에 적지 않습니다. 나중에 바꿀 때는 메뉴 **황소 장부 → 비밀번호 설정** 을 쓰거나, 같은 스크립트 속성 값을 수정합니다.

### 4. 웹 앱으로 배포

1. Apps Script 오른쪽 위 **배포 → 새 배포**
2. 톱니바퀴에서 유형 **웹 앱**
3. 설명은 아무거나 (예: 황소 장부)
4. 실행 계정: **나**
5. 액세스 권한: **모든 사용자** (영문 화면이면 **Anyone**). 구글 로그인을 요구하는 항목이 아닙니다.
6. **배포**를 누르고, 끝나는 주소가 `/exec` 인 **웹 앱 URL** 을 복사합니다. `/dev` 주소는 쓰지 않습니다.

스크립트를 나중에 고치면 **배포 → 배포 관리 → 연필 → 버전: 새 버전 → 배포** 를 해야 페이지가 새 코드를 사용합니다.

### 5. 페이지 주소

`Workbook_Ledger/index.html` 의 `SCRIPT_URL` 은 배포된 웹 앱 주소입니다.

```text
https://script.google.com/macros/s/AKfycbyShKol-v2lx0OTwMFHcZ-QQMqMbRpWXT_4yi0jvvCWjcJtG3EB1uQvJDBd3Rty0g/exec
```

웹 앱을 새로 배포해 주소가 바뀌면 이 값만 새 `/exec` 주소로 바꿉니다. 깃허브에 반영된 뒤 1분 정도 지나 https://for1916.github.io/1916/Workbook_Ledger/ 를 열고 비밀번호를 입력합니다.

비밀번호는 그 브라우저 탭의 `sessionStorage` 에만 있습니다. 탭을 닫으면 다시 묻습니다.

## 초기 설정이 시트에서 하는 일

이미 맞춰진 시트에서 다시 실행해도 됩니다.

- `수입` 시트를 **날짜, 금액, 메모**만 남깁니다. 주문자, 구분, 내용(교재·권수) 열은 지웁니다. 구분이 `주문 입금` 이던 행은 주문 연동과 같은 판매이므로 지웁니다. 그 외 행은 주문에 없는 판매로 남습니다.
- `주문 연동` 은 원본 `주문 관리` 의 **제출일시, 상태, 금액**만 가져옵니다. 주문자, 연락처, 교재는 가져오지 않습니다. 금액 글자 `40,000원` 은 숫자로 바꾸고, 날짜 글자 `2026. 7. 13` 은 날짜로 바꿉니다.
- `지출` 은 **날짜, 분류, 항목, 금액, 메모**만 남깁니다. 거래처와 결제수단 열은 지웁니다. 예전 분류는 이렇게 옮깁니다. 교재 제작비·교재 구매비 → 제본, 구독료(AI·툴) → AI, 광고비 → 광고, 박스·포장재·택배비 → 박스. 수수료·기타처럼 네 가지에 없는 분류는 그대로 두고, 메모에 `이전 분류:` 를 적습니다. 월별 합계의 네 칸에는 들어가지 않으니, 알림에 나오면 직접 바꿔 주세요.
- `분류` 시트는 제본, AI, 광고, 박스만 남깁니다.
- `월별 요약` 은 월, 판매, 제본, AI, 광고, 박스, 총지출, 순이익, 이익률과 합계 행으로 다시 씁니다. 첫 달은 2026-06이고, 수입·지출·주문 연동에 그보다 이른 날짜나 더 늦은 날짜가 있으면 그 달까지 행을 늘립니다. 마지막 달은 적어도 이번 달부터 12개월 뒤입니다. 이 탭의 수식만 다시 쓰고, 수입·지출·주문 연동의 데이터는 바꾸지 않습니다. 판매는 취소·환불이 아닌 주문 금액과, 수입 시트에 남은 금액을 더합니다.
- 주문자·연락처·교재·예전 열 이름을 설명하던 안내 문구를 지금 구조에 맞게 바꿉니다.
- 재고 탭 `재고 품목`, `입출고`, `현재 재고`, `주문 출고`를 만들거나 헤더만 맞춥니다. 이미 있는 기초 수량, 최소 재고, 단위당개수, 박스 규칙은 덮어쓰지 않습니다.

주문 연동에 이미 있는 판매를 수입 시트에 다시 적으면 두 번 합산됩니다. 화면의 판매 목록에서 그 직접 입력 행을 지우면 됩니다.

### 재고 탭을 나누는 이유

`재고 품목`, `입출고`, `현재 재고` 세 탭이 재고의 본체입니다. 여기에 `주문 출고`를 하나 더 둔 이유는, 이익용 `주문 연동`이 교재를 가져오면 안 되기 때문입니다. 주문에서 출고를 계산하려면 교재 글자 `4-1 (1권)` 가 필요한데, 그 글자를 이익 시트나 직접 입력한 입출고 칸에 섞지 않으려고 가져오기 전용 탭을 두었습니다. 가져오는 열은 제출일시, 상태, 교재뿐입니다.

처음 실행하면 교재 `4-1`, `4-2`, `5-1`, `5-2`, `6-1`, `6-2`를 품목에 넣습니다. 박스 품목이 하나도 없을 때만 예시로 `박스-소`, `박스-중`, `박스-대`를 넣습니다. 구매단위는 팩이고, **단위당개수는 1**입니다. 1팩이 10개면 그 칸을 10으로 바꾸세요. 최소 재고는 0입니다. 0이면 재고가 마이너스일 때만 부족으로 표시하니, 필요한 품목만 최소 재고를 올리세요.

박스 규칙 예시는 한 번만 넣습니다. 교재 1권은 작은 박스 1개, 2–3권은 중간 박스 1개, 4–20권은 큰 박스 1개입니다. 주문 권수에 맞는 **위에서부터 첫 규칙**을 쓰고, 박스는 주문당 한 번만 뺍니다. 규칙을 모두 지운 뒤 초기 설정을 다시 해도 예시는 다시 채워지지 않습니다. 박스 품목을 전부 지우면 다음 초기 설정에서 예시 박스 세 개가 다시 들어옵니다.

현재 재고는 `기초 + 입고 − 출고 + 조정`입니다. 입고·출고·조정은 `입출고`의 환산수량으로 더합니다. 팩으로 적은 수량은 그 품목의 단위당개수를 곱해 개로 바꿉니다.

## 화면에서 하는 일

- 비밀번호를 통과해야 숫자가 보입니다.
- **입력** 에서 지출을 넣습니다. 날짜, 분류(제본·AI·광고·박스), 금액, 메모입니다.
- **내역** 에서 지출을 수정·삭제합니다. 주문은 읽기만 되고, 수입 시트에 직접 적은 판매만 수정·삭제할 수 있습니다.
- **월별 요약** 에서 판매, 제본, AI, 광고, 박스, 총지출, 순이익, 이익률과 분류별 막대를 봅니다. 달은 2026년 6월부터 시작하고, 장부에 있는 가장 이른 달과 가장 늦은 달, 그리고 이번 달부터 12개월 뒤를 모두 포함합니다.
- **재고** 에서 현재 수량과 부족 품목을 봅니다. 입고, 직접 출고·조정, 박스 규칙, 품목(단위당개수·최소 재고)을 이 화면에서 넣습니다. 주문 출고는 읽기만 됩니다. 재고 탭을 열거나 **재고 새로고침**을 누를 때만 주문을 다시 읽고, 이익 화면을 열 때마다 재고를 다시 계산하지는 않습니다.

## 도우미가 같은 웹 앱으로 행을 추가할 때

비밀번호를 요청 본문에 넣어 `POST` 합니다. 주소 쿼리에 비밀번호를 붙이지 마세요. 아래 주소는 배포한 `/exec` 주소입니다.

지출 한 줄:

```bash
curl -L --post301 --post302 --post303 \
  -X POST 'https://script.google.com/macros/s/AKfycbyShKol-v2lx0OTwMFHcZ-QQMqMbRpWXT_4yi0jvvCWjcJtG3EB1uQvJDBd3Rty0g/exec' \
  -H 'Content-Type: text/plain;charset=utf-8' \
  --data '{"password":"비밀번호","action":"add","sheet":"지출","record":{"날짜":"2026-10-09","분류":"박스","금액":4500,"메모":"포장 박스"}}'
```

분류는 `제본`, `AI`, `광고`, `박스` 만 됩니다. 예전 이름 `광고비` 처럼 적어도 맞는 분류로 저장됩니다. `거래처`, `결제수단`, `주문자` 는 저장되지 않습니다.

주문에 없는 판매만, 수입 시트에 날짜·금액·메모로 넣을 수 있습니다. 주문 연동에 있는 40,000원 같은 판매는 넣지 마세요.

```bash
curl -L --post301 --post302 --post303 \
  -X POST 'https://script.google.com/macros/s/AKfycbyShKol-v2lx0OTwMFHcZ-QQMqMbRpWXT_4yi0jvvCWjcJtG3EB1uQvJDBd3Rty0g/exec' \
  -H 'Content-Type: text/plain;charset=utf-8' \
  --data '{"password":"비밀번호","action":"add","sheet":"수입","record":{"날짜":"2026-10-09","금액":40000,"메모":"주문 연동에 없는 판매"}}'
```

`--post301` 옵션은 구글이 주소를 다른 곳으로 넘겨도 본문이 유지되게 합니다.

목록을 읽을 때:

```bash
curl -L --post301 --post302 --post303 \
  -X POST 'https://script.google.com/macros/s/AKfycbyShKol-v2lx0OTwMFHcZ-QQMqMbRpWXT_4yi0jvvCWjcJtG3EB1uQvJDBd3Rty0g/exec' \
  -H 'Content-Type: text/plain;charset=utf-8' \
  --data '{"password":"비밀번호","action":"load"}'
```

수정·삭제는 시트 행 번호와, 그 행의 현재 날짜·금액이 같아야 합니다.

```bash
curl -L --post301 --post302 --post303 \
  -X POST 'https://script.google.com/macros/s/AKfycbyShKol-v2lx0OTwMFHcZ-QQMqMbRpWXT_4yi0jvvCWjcJtG3EB1uQvJDBd3Rty0g/exec' \
  -H 'Content-Type: text/plain;charset=utf-8' \
  --data '{"password":"비밀번호","action":"update","sheet":"지출","row":5,"match":{"date":"2026-10-09","amount":4500},"record":{"날짜":"2026-10-09","분류":"박스","금액":5000,"메모":"포장 박스"}}'
```

```bash
curl -L --post301 --post302 --post303 \
  -X POST 'https://script.google.com/macros/s/AKfycbyShKol-v2lx0OTwMFHcZ-QQMqMbRpWXT_4yi0jvvCWjcJtG3EB1uQvJDBd3Rty0g/exec' \
  -H 'Content-Type: text/plain;charset=utf-8' \
  --data '{"password":"비밀번호","action":"delete","sheet":"지출","row":5,"match":{"date":"2026-10-09","amount":4500}}'
```

`주문자`, `연락처`, `주소` 같은 키를 넣으면 거절합니다. 주문 연동 시트는 이 API로 수정할 수 없습니다. 항목은 시트에 열로 남아 있으며, 요청에 `항목` 을 넣을 때만 바뀝니다.

### 아침 재고 확인

비밀번호가 있어야 합니다. 응답의 `items` 가 품목별 현재 재고이고, `low` 가 최소 재고보다 적은 품목입니다. `importReady` 가 false 이면 주문 출고 시트의 액세스 허용이 아직입니다.

```bash
curl -L --post301 --post302 --post303 \
```

주문에서 만들어진 출고 행은 수정·삭제되지 않습니다. 품목의 최소 재고와 단위당개수는 `sheet` 를 `재고 품목` 으로 하고 `코드` 를 맞춰 `update` 합니다. 박스 규칙은 `sheet` 를 `박스규칙` 으로 하고 `최소권수`, `최대권수`, `박스코드`, `박스개수` 를 넣습니다.

## 잘 안 될 때

- 비밀번호가 맞는데 `비밀번호가 아직 설정되지 않았습니다` → 스크립트 속성 이름이 정확히 `LEDGER_PASSWORD` 인지 확인하고, 웹 앱을 **새 버전**으로 다시 배포합니다.
- 페이지가 응답을 읽지 못함 → 배포 액세스 권한이 **모든 사용자**인지, 주소가 `/exec` 로 끝나는지 확인합니다.
- 판매가 0인데 주문은 있음 → `주문 연동` 에서 액세스 허용을 눌렀는지, 상태 칸에 취소·환불이 적혀 있지 않은지 확인합니다. 2026년 7월 13일 40,000원 주문은 그 달 판매에 보여야 합니다. 원본 제출일시가 `₩46,216`처럼 보이면 날짜 숫자가 통화 서식으로 보인 것입니다. `Code.gs`를 다시 붙여 넣고 **초기 설정**을 실행하면 날짜 숫자와 `2026. 7. 13` 글자를 모두 날짜로 바꿉니다.
- 수입 열이나 주문 연동 옆 칸에 `주문 입금`, `기타 수입`, `네이버폼`, `집계 포함` 같은 예전 안내가 남아 있으면 **초기 설정**이 그 칸을 지웁니다. 지금 쓰는 안내는 `[장부 안내]`로 시작합니다.
- **황소 장부 → 개인정보 열 점검** 에 개인정보 열이 남아 있다고 나오면 **초기 설정**을 한 번 더 실행합니다.
- 재고가 비어 있거나 예전 스크립트와 같음 → `Code.gs` 를 다시 붙여 넣고 저장한 뒤 **황소 장부 → 초기 설정**을 실행하고, 웹 앱을 **새 버전**으로 다시 배포합니다. 배포 주소가 바뀌지 않았으면 `index.html` 의 `SCRIPT_URL` 은 그대로 둡니다.
- 주문했는데 교재 재고가 안 줄어듦 → `주문 출고` 시트에서 액세스 허용을 눌렀는지 확인하고, **재고 새로고침**을 실행합니다. 상태가 취소 또는 환불인 주문은 빼지 않습니다.
