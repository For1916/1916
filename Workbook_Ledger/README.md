# 황소 워크북 장부

판매와 지출만 보고 **황소 워크북**의 이익 구조를 확인하는 페이지입니다. 깃허브 페이지의 화면과, 구글 시트 `황소 워크북 장부`에 붙이는 Apps Script 웹 앱으로 이루어져 있습니다.

이 장부에는 주문자 이름, 전화번호, 주소, 모아폼 답변 번호, 유입 경로를 저장하거나 보여 주지 않습니다. 판매는 `주문 연동`의 날짜·상태·금액만 사용하고, 상태가 취소 또는 환불인 주문은 뺍니다. 지출 분류는 **제본, AI, 광고, 박스** 네 가지입니다.

화면 주소(배포 후): https://for1916.github.io/1916/Workbook_Ledger/

## 파일

| 파일 | 역할 |
| --- | --- |
| `index.html` | 장부 화면. 깃허브 페이지가 이 파일을 엽니다. |
| `apps-script/Code.gs` | 시트에 붙여 넣을 스크립트. 읽기·추가·수정·삭제와 개인정보 열 정리를 합니다. |

## 배포

개발 도구를 쓰지 않아도 됩니다. 아래 순서만 따라 하면 됩니다.

### 1. 스크립트 붙여 넣기

1. 구글 시트 **황소 워크북 장부**를 엽니다.
2. 메뉴 **확장 프로그램 → Apps Script** 를 누릅니다.
3. 편집기에 있는 `Code.gs` 내용을 모두 지우고, 이 폴더의 `apps-script/Code.gs` **전체**를 붙여 넣습니다.
4. 디스켓 아이콘으로 저장합니다.
5. 왼쪽 톱니바퀴 **프로젝트 설정**에서 다음을 확인합니다.
   - 시간대: **(GMT+09:00) 서울**
   - 런타임: **Chrome V8**

### 2. 초기 설정을 한 번 실행

이 단계가 시트에서 개인정보 열을 지웁니다. 이미 지워진 상태에서 다시 실행해도 됩니다.

1. 시트 탭으로 돌아가 **새로고침**합니다.
2. 상단 메뉴에 **황소 장부**가 보이면 **황소 장부 → 초기 설정**을 누릅니다.
3. 비밀번호를 묻는 창이 나오면, 웹 장부에 쓸 비밀번호를 입력하고 확인을 누릅니다. 4자 이상으로 길게 정하세요. 웹 주소는 공개되어도 이 비밀번호 없이는 내용을 볼 수 없습니다.
4. 구글이 권한을 물어보면 본인 계정을 고르고 **허용**을 누릅니다. 시트 주인인 본인 스크립트라서 별도 보안 예외를 켤 필요는 없습니다.

메뉴가 보이지 않으면 Apps Script 편집기에서 함수 목록의 **setup** 을 고르고 실행을 누릅니다. 편집기 실행에서는 비밀번호 창이 뜨지 않을 수 있습니다. 그때는 3번의 스크립트 속성으로 비밀번호를 넣습니다. `setup` 은 비밀번호가 없어도 열 정리는 진행합니다.

`주문 연동` 시트에 `#REF!` 와 함께 **액세스 허용**이 보이면 그 버튼을 누릅니다. 다른 시트의 주문 목록을 다시 가져오는 허락입니다.

### 3. 비밀번호를 스크립트 속성에 두기

메뉴에서 비밀번호를 저장했다면 이 단계는 건너뜁니다. 저장됐는지는 **황소 장부 → 개인정보 열 점검** 에서 `비밀번호: 설정됨` 으로 확인합니다.

직접 넣을 때:

1. Apps Script **프로젝트 설정 → 스크립트 속성 → 스크립트 속성 추가**
2. 속성: `LEDGER_PASSWORD`
3. 값: 사용할 비밀번호
4. 저장

비밀번호는 HTML이나 깃허브에 적지 않습니다. 나중에 바꿀 때는 메뉴 **황소 장부 → 비밀번호 설정** 을 쓰거나, 같은 스크립트 속성 값을 수정합니다.

### 4. 웹 앱으로 배포

1. Apps Script 오른쪽 위 **배포 → 새 배포**
2. 톱니바퀴에서 유형 **웹 앱**
3. 설명은 아무거나 (예: 황소 장부)
4. 실행 계정: **나**
5. 액세스 권한: **모든 사용자** (영문 화면이면 **Anyone**). 구글 로그인을 요구하는 항목이 아닙니다.
6. **배포**를 누르고, 끝나는 주소가 `/exec` 인 **웹 앱 URL** 을 복사합니다. `/dev` 주소는 쓰지 않습니다.

스크립트를 나중에 고치면 **배포 → 배포 관리 → 연필 → 버전: 새 버전 → 배포** 를 해야 페이지가 새 코드를 사용합니다.

### 5. 페이지에 주소 넣기

1. `Workbook_Ledger/index.html` 을 엽니다.
2. 아래 글자를 찾아, 방금 복사한 `/exec` 주소로 **그 글자만** 바꿉니다.

```text
PASTE_YOUR_APPS_SCRIPT_WEB_APP_URL_HERE
```

3. 저장하고 깃허브에 커밋합니다. 깃허브 웹사이트에서 이 파일을 연 뒤 연필 아이콘으로 고쳐도 됩니다.
4. 1분 정도 뒤에 https://for1916.github.io/1916/Workbook_Ledger/ 를 열고 비밀번호를 입력합니다.

비밀번호는 그 브라우저 탭의 `sessionStorage` 에만 있습니다. 탭을 닫으면 다시 묻습니다.

## 초기 설정이 시트에서 하는 일

이미 맞춰진 시트에서 다시 실행해도 됩니다.

- `수입` 시트를 **날짜, 금액, 메모**만 남깁니다. 주문자, 구분, 내용(교재·권수) 열은 지웁니다. 구분이 `주문 입금` 이던 행은 주문 연동과 같은 판매이므로 지웁니다. 그 외 행은 주문에 없는 판매로 남습니다.
- `주문 연동` 은 원본 `주문 관리` 의 **제출일시, 상태, 금액**만 가져옵니다. 주문자, 연락처, 교재는 가져오지 않습니다. 금액 글자 `40,000원` 은 숫자로 바꾸고, 날짜 글자 `2026. 7. 13` 은 날짜로 바꿉니다.
- `지출` 은 **날짜, 분류, 항목, 금액, 메모**만 남깁니다. 거래처와 결제수단 열은 지웁니다. 예전 분류는 이렇게 옮깁니다. 교재 제작비·교재 구매비 → 제본, 구독료(AI·툴) → AI, 광고비 → 광고, 박스·포장재·택배비 → 박스. 수수료·기타처럼 네 가지에 없는 분류는 그대로 두고, 메모에 `이전 분류:` 를 적습니다. 월별 합계의 네 칸에는 들어가지 않으니, 알림에 나오면 직접 바꿔 주세요.
- `분류` 시트는 제본, AI, 광고, 박스만 남깁니다.
- `월별 요약` 은 월, 판매, 제본, AI, 광고, 박스, 총지출, 순이익, 이익률과 합계 행으로 다시 씁니다. 판매는 취소·환불이 아닌 주문 금액과, 수입 시트에 남은 금액을 더합니다.
- 주문자·연락처·교재·예전 열 이름을 설명하던 안내 문구를 지금 구조에 맞게 바꿉니다.

주문 연동에 이미 있는 판매를 수입 시트에 다시 적으면 두 번 합산됩니다. 화면의 판매 목록에서 그 직접 입력 행을 지우면 됩니다.

## 화면에서 하는 일

- 비밀번호를 통과해야 숫자가 보입니다.
- **입력** 에서 지출을 넣습니다. 날짜, 분류(제본·AI·광고·박스), 금액, 메모입니다.
- **내역** 에서 지출을 수정·삭제합니다. 주문은 읽기만 되고, 수입 시트에 직접 적은 판매만 수정·삭제할 수 있습니다.
- **월별 요약** 에서 판매, 제본, AI, 광고, 박스, 총지출, 순이익, 이익률과 분류별 막대를 봅니다.

## 도우미가 같은 웹 앱으로 행을 추가할 때

비밀번호를 요청 본문에 넣어 `POST` 합니다. 주소 쿼리에 비밀번호를 붙이지 마세요. 아래 주소의 `PASTE_YOUR_APPS_SCRIPT_WEB_APP_URL_HERE` 는 배포한 `/exec` 주소입니다.

지출 한 줄:

```bash
curl -L --post301 --post302 --post303 \
  -X POST 'PASTE_YOUR_APPS_SCRIPT_WEB_APP_URL_HERE' \
  -H 'Content-Type: text/plain;charset=utf-8' \
  --data '{"password":"비밀번호","action":"add","sheet":"지출","record":{"날짜":"2026-10-09","분류":"박스","금액":4500,"메모":"포장 박스"}}'
```

분류는 `제본`, `AI`, `광고`, `박스` 만 됩니다. 예전 이름 `광고비` 처럼 적어도 맞는 분류로 저장됩니다. `거래처`, `결제수단`, `주문자` 는 저장되지 않습니다.

주문에 없는 판매만, 수입 시트에 날짜·금액·메모로 넣을 수 있습니다. 주문 연동에 있는 40,000원 같은 판매는 넣지 마세요.

```bash
curl -L --post301 --post302 --post303 \
  -X POST 'PASTE_YOUR_APPS_SCRIPT_WEB_APP_URL_HERE' \
  -H 'Content-Type: text/plain;charset=utf-8' \
  --data '{"password":"비밀번호","action":"add","sheet":"수입","record":{"날짜":"2026-10-09","금액":40000,"메모":"주문 연동에 없는 판매"}}'
```

`--post301` 옵션은 구글이 주소를 다른 곳으로 넘겨도 본문이 유지되게 합니다.

목록을 읽을 때:

```bash
curl -L --post301 --post302 --post303 \
  -X POST 'PASTE_YOUR_APPS_SCRIPT_WEB_APP_URL_HERE' \
  -H 'Content-Type: text/plain;charset=utf-8' \
  --data '{"password":"비밀번호","action":"load"}'
```

수정·삭제는 시트 행 번호와, 그 행의 현재 날짜·금액이 같아야 합니다.

```bash
curl -L --post301 --post302 --post303 \
  -X POST 'PASTE_YOUR_APPS_SCRIPT_WEB_APP_URL_HERE' \
  -H 'Content-Type: text/plain;charset=utf-8' \
  --data '{"password":"비밀번호","action":"update","sheet":"지출","row":5,"match":{"date":"2026-10-09","amount":4500},"record":{"날짜":"2026-10-09","분류":"박스","금액":5000,"메모":"포장 박스"}}'
```

```bash
curl -L --post301 --post302 --post303 \
  -X POST 'PASTE_YOUR_APPS_SCRIPT_WEB_APP_URL_HERE' \
  -H 'Content-Type: text/plain;charset=utf-8' \
  --data '{"password":"비밀번호","action":"delete","sheet":"지출","row":5,"match":{"date":"2026-10-09","amount":4500}}'
```

`주문자`, `연락처`, `주소` 같은 키를 넣으면 거절합니다. 주문 연동 시트는 이 API로 수정할 수 없습니다. 항목은 시트에 열로 남아 있으며, 요청에 `항목` 을 넣을 때만 바뀝니다.

## 잘 안 될 때

- 비밀번호가 맞는데 `비밀번호가 아직 설정되지 않았습니다` → 스크립트 속성 이름이 정확히 `LEDGER_PASSWORD` 인지 확인하고, 웹 앱을 **새 버전**으로 다시 배포합니다.
- 페이지가 응답을 읽지 못함 → 배포 액세스 권한이 **모든 사용자**인지, 주소가 `/exec` 로 끝나는지 확인합니다.
- 판매가 0인데 주문은 있음 → `주문 연동` 에서 액세스 허용을 눌렀는지, 상태 칸에 취소·환불이 적혀 있지 않은지 확인합니다. 2026년 7월 13일 40,000원 주문은 그 달 판매에 보여야 합니다.
- **황소 장부 → 개인정보 열 점검** 에 개인정보 열이 남아 있다고 나오면 **초기 설정**을 한 번 더 실행합니다.
