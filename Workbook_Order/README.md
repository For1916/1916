# 황소 워크북 주문

모아폼 대신 쓰는 공개 주문서입니다. 학부모가 교재와 수량을 고르고, 입금 안내를 본 뒤 배송지를 남기면 구글 시트 `황소 워크북 주문 관리`의 `주문 관리` 탭에 한 줄이 붙습니다.

화면 주소: https://for1916.github.io/1916/Workbook_Order/

장부 페이지와 시각 스타일을 같게 맞춰 두었습니다. 이 주문서는 비밀번호가 없고, 이미 들어온 주문을 보여 주지 않습니다. 서버도 기존 행을 응답으로 돌려주지 않습니다.

## 파일

| 파일 | 역할 |
| --- | --- |
| `index.html` | 공개 주문서. 깃허브 페이지가 이 파일을 엽니다. |
| `apps-script/Code.gs` | 독립 실행형 Apps Script. 시트에 묶지 않고 `openById`로 주문 시트를 엽니다. |

## 사장님이 확인할 값

가격은 **임시 기본값 권당 40,000원**입니다. 4-1, 4-2, 5-1, 5-2, 6-1, 6-2가 모두 같습니다. 실제 판매가와 다르면 두 곳의 숫자를 같이 바꾸세요.

1. `index.html`의 `ORDER_CONFIG.products[].price`
2. `apps-script/Code.gs`의 `PRODUCTS[].price`

화면은 1번으로 금액을 보여주고, 서버는 2번으로 다시 계산합니다. 두 금액이 다르면 주문이 거절됩니다. 가격을 바꾼 뒤에는 스크립트를 **새 버전으로 다시 배포**해야 서버가 바뀝니다.

4-1 이름만 `황소 워크북 4-1 (일품·실력 겸용)`입니다. 나머지 권은 `황소 워크북 4-2`처럼 코드만 붙였습니다.

받는 계좌는 **신한은행 110-351-100566**입니다. 계좌의 예금주 이름은 이 주문서에 적혀 있지 않습니다. 화면에 보이려면 `ORDER_CONFIG.ACCOUNT_HOLDER`에 이름을 넣으세요. 비어 있으면 예금주 줄은 나오지 않습니다.

아직 비어 있는 자리표시자:

| 위치 | 이름 | 넣을 값 |
| --- | --- | --- |
| `index.html` `ORDER_CONFIG.SCRIPT_URL` | `PASTE_WEB_APP_URL_HERE` | 웹 앱 배포 주소. `/exec`로 끝나야 합니다. |

도로명주소 검색 승인키는 `ORDER_CONFIG.JUSO_CONFM_KEY`에 이미 들어가 있습니다.

## 주문서가 받는 내용

모두 필수입니다. 화면과 서버가 같은 규칙으로 거절합니다.

- 교재: 위 여섯 권 중 수량이 1 이상인 것. 한 권당 최대 30권, 한 주문 합계 최대 60권.
- 유입 플랫폼: 인스타그램, 블로그, 카페, 지인 추천, 기타. 기타는 짧은 설명을 적어야 합니다.
- 주문자(예금주): `이름_전화번호뒤4자리`. 예: `도진우_1916`. 한글 이름 2~20자, 밑줄, 숫자 4개.
- 연락처: 한국 휴대폰. `010-1234-5678`처럼 저장합니다.
- 배송지: 행정안전부 도로명주소 **검색 API**로 고른 도로명주소, 상세주소, 우편번호 5자리. 배송비는 착불입니다.
- 동의 두 칸: 개인정보 수집·이용, 주문·입금·착불 안내. 각각 앞뒤 공백을 뺀 값이 정확히 `동의합니다`여야 합니다.
- 송금하셨나요?: `네, 완료했습니다` 또는 `아니요, 곧 송금하겠습니다`.

입금 안내: 신한은행 110-351-100566. 총 입금 금액은 고른 수량으로 바로 계산됩니다. 제출 시각 기준 **전후 30분** 안의 입금만 그 주문으로 보고, 입금자명은 밑줄 앞의 이름, 금액은 총 입금 금액과 같아야 합니다. 배송비는 그 금액에 넣지 않습니다.

봇 거절: 숨은 칸이 채워져 있거나, 페이지를 연 뒤 5초가 안 됐거나, 같은 연락처로 30분 안에 4번째 주문이면 저장하지 않습니다.

## 시트에 들어가는 값

헤더 이름으로 열을 찾습니다. 열 순서가 조금 달라도 헤더가 같으면 그 칸에 씁니다. 아래 헤더가 없으면 주문을 거절합니다.

| 헤더 | 예시 |
| --- | --- |
| 제출일시 | 서울 시각의 실제 날짜·시간. 글자가 아니라 날짜 값입니다. |
| 상태 | `신규` |
| 주문자(예금주) | `도진우_1916` |
| 연락처 | `010-1234-5678` |
| 교재 | `4-1 (1권), 5-1 (2권)` |
| 금액 | 숫자 `120000` |
| 우편번호 | `04524` (문자로 저장해 앞자리 0이 사라지지 않습니다) |
| 주소 | 도로명주소와 상세주소 |
| 유입 플랫폼 | `인스타그램` 또는 `기타: 유튜브` |
| 메모 | `송금: 네, 완료했습니다` |
| 모아폼 답변 ID | 주문 번호. 예: `WB261010-K7QP` |
| 모아폼 결과 URL | 빈칸 |
| 주문자 원본 (숨김) | 입력한 주문자 문자열 |
| 교재 원본 (숨김) | `황소 워크북 4-1 (일품·실력 겸용) 1권, 황소 워크북 5-1 2권` |

교재 칸은 장부 재고가 읽는 형식입니다. 코드, 공백, `(N권)`이고 권과 권 사이는 `, `입니다. 장부는 취소·환불이 아닌 `신규` 주문의 금액을 판매로 잡고, 교재 권수만큼 재고를 뺍니다.

저장 뒤에 스크립트 실행 계정(`Session.getEffectiveUser`)으로 주문 요약 메일을 보냅니다. 메일 발송이 실패해도 시트 행은 남고, 고객에게는 주문 번호가 보입니다. 응답에는 방금 만든 주문 번호, 금액, 교재 요약, 입금자명, 제출 시각만 있고 다른 주문의 내용은 없습니다.

## 배포

개발 도구 없이 아래 순서만 따라 하면 됩니다. 이 스크립트는 장부 시트에 붙이지 않습니다. 장부용 Apps Script와 프로젝트를 따로 둡니다.

### 1. 스크립트 붙여 넣기

1. 브라우저에서 https://script.google.com 을 엽니다. 주문 시트를 수정할 수 있는 계정이어야 합니다.
2. **새 프로젝트**를 만듭니다. 스프레드시트 메뉴의 확장 프로그램으로 열지 않습니다.
3. 기본 `Code.gs` 내용을 모두 지우고, 이 폴더의 `apps-script/Code.gs` **전체**를 붙여 넣습니다.
4. 프로젝트 이름을 `황소 워크북 주문`으로 바꿉니다.
5. 저장합니다.
6. 왼쪽 톱니바퀴 **프로젝트 설정**에서 시간대를 **(GMT+09:00) 서울**, 런타임을 **Chrome V8**로 둡니다.

스프레드시트 `황소 워크북 주문 관리`의 시간대도 서울이어야 제출일시가 서울 시각으로 보입니다. 시트 **파일 → 설정 → 시간대**를 확인하세요. 시간대를 바꾸면 기존 날짜의 보이는 시각이 달라질 수 있으니, 이미 서울이면 그대로 둡니다.

### 2. 웹 앱으로 배포

1. 오른쪽 위 **배포 → 새 배포**
2. 톱니바퀴에서 유형 **웹 앱**
3. 설명 예: `황소 주문`
4. 실행 계정: **나**
5. 액세스 권한: **모든 사용자** (영문 화면이면 **Anyone**). 구글 로그인을 요구하는 항목이 아닙니다.
6. **배포**를 누릅니다. 스프레드시트 수정과 메일 보내기 권한을 물으면 본인 계정으로 **허용**합니다.
7. 끝나는 주소가 `/exec`인 **웹 앱 URL**을 복사합니다. `/dev` 주소는 쓰지 않습니다.

코드를 나중에 고치면 **배포 → 배포 관리 → 연필 → 버전: 새 버전 → 배포**를 해야 페이지가 새 코드를 사용합니다. 같은 배포를 갱신하면 주소는 유지됩니다.

### 3. 페이지에 주소 넣기

`Workbook_Order/index.html`의 `ORDER_CONFIG.SCRIPT_URL`을 복사한 `/exec` 주소로 바꿉니다.

```text
PASTE_WEB_APP_URL_HERE
```

깃허브에 반영된 뒤 1분 정도 지나 화면을 새로고침합니다. 자리표시자가 남아 있으면 페이지 위에 노란 안내가 나옵니다.

### 4. 도로명주소 승인키

주소 검색은 브라우저가 행정안전부 검색 API를 직접 호출합니다.

```text
https://business.juso.go.kr/addrlink/addrLinkApi.do
```

승인키는 도메인에 묶이므로 구글 서버를 거치지 않습니다. 신청 종류는 **검색 API**여야 합니다. 팝업 API 승인키는 이 페이지에서 동작하지 않습니다.

승인키는 `ORDER_CONFIG.JUSO_CONFM_KEY`에 넣어 두었습니다. 신청 도메인은 `for1916.github.io`이고, 페이지 주소는 https://for1916.github.io/1916/Workbook_Order/ 입니다.

키는 페이지 소스에 보입니다. 검색 API 키는 등록한 도메인에서만 쓰도록 발급되므로, 그 도메인 제한이 공개된 키를 막아 줍니다.

### 5. 시험 주문

1. https://for1916.github.io/1916/Workbook_Order/ 를 엽니다. 자리표시자 안내가 없어야 합니다.
2. 4-1을 1권만 올리고 총 입금 금액이 40,000원인지 봅니다. 가격을 바꿨다면 그 금액인지 봅니다.
3. 주문자에 `도진우_1916` 형식, 연락처에 본인 휴대폰을 넣습니다. 밑줄 앞 이름이 입금자명으로 보이는지 확인합니다.
4. **도로명주소 검색**으로 목록에서 주소를 고르고 상세주소를 적습니다.
5. 유입 플랫폼과 `송금하셨나요?`를 고릅니다.
6. 동의 칸 두 곳에 `동의합니다`를 그대로 적습니다. `동의 합니다`나 마침표가 있으면 거절되는지 한 번 확인해 보세요.
7. 페이지를 연 뒤 5초가 지나기 전에 제출하면 거절됩니다. 잠시 뒤 다시 제출합니다.
8. 감사합니다 화면에 주문 번호 `WB`로 시작하는 값, 계좌, 금액, 입금자명, 전후 30분이 보이는지 확인합니다.
9. 시트 `주문 관리` 맨 아래에 행이 생겼는지 봅니다. 제출일시가 날짜인지, 상태가 `신규`인지, 교재가 `4-1 (1권)`인지, 금액이 숫자인지, 모아폼 답변 ID가 화면의 주문 번호와 같은지 확인합니다.
10. 실행 계정 메일함에 `[황소 워크북] 새 주문` 메일이 왔는지 봅니다.
11. 시험 행은 지우거나 상태를 `취소`로 바꿉니다. `신규`로 두면 장부 판매와 재고 출고에 포함됩니다. 같은 연락처로는 30분에 3건까지입니다.

체크만 하고 제출하지 않는 확인:

- 교재 0권, 잘못된 주문자 `도진우1916`, 일반 전화, 주소 검색 없이 제출하면 각 항목 오류가 납니다.
- 숨은 칸은 사람이 보지 못합니다. 자동입력으로 채워지면 접수되지 않습니다.

## 모아폼에서 바꾸기

1. 위 시험 주문으로 시트 행, 메일, 주문 번호가 맞는지 확인합니다. 시험 행은 `취소`로 바꾸거나 지웁니다.
2. 장부 시트에서 `주문 연동`이 제출일시·상태·금액만, `주문 출고`가 제출일시·상태·교재만 가져오는지 그대로 둡니다. 교재 글자가 `4-1 (1권)`이면 재고 계산이 그 권수를 읽습니다.
3. 인스타그램, 블로그, 카페에 올려 둔 모아폼 링크를 이 주소로 바꿉니다. https://for1916.github.io/1916/Workbook_Order/
4. 모아폼 양식을 마감합니다. 마감하지 않으면 새 주문이 두 곳으로 나뉩니다.
5. 이미 쌓인 모아폼 행은 그대로 둡니다. 새 행은 그 아래에 붙습니다. 모아폼 답변 ID 칸에는 이제 `WB261010-K7QP` 같은 주문 번호가 들어가고, 모아폼 결과 URL은 비워 둡니다.

## 잘 안 될 때

- 페이지 위 노란 글이 보임 → `SCRIPT_URL`이 아직 자리표시자입니다. 웹 앱을 배포한 뒤 `/exec` 주소를 넣으세요.
- 주소 검색이 `승인되지 않은 KEY` → 검색 API 키인지, 도메인 `for1916.github.io`가 등록됐는지 확인합니다. 팝업 API 키는 쓸 수 없습니다.
- 제출 뒤 `서버 응답을 읽지 못했습니다` → 배포 액세스가 **모든 사용자**인지, 주소가 `/exec`인지 확인합니다.
- `주문 시트를 열 수 없습니다` → 웹 앱을 배포한 계정이 스프레드시트 `황소 워크북 주문 관리`를 수정할 수 있는지 확인합니다. 권한을 바꾼 뒤에는 배포를 새 버전으로 올립니다.
- `시트 헤더 [...] 를 찾지 못했습니다` → `주문 관리` 첫 줄 헤더 이름이 위 표와 같은지 확인합니다. 공백 차이는 무시하지만, 헤더 자체가 없으면 그 행을 쓰지 않습니다.
- 메일이 없음 → 시트 행이 있으면 주문은 저장된 것입니다. 실행 계정의 보낸편지함과 스팸함을 확인하고, 메일 권한을 허용한 배포인지 봅니다.
- 금액이 거절됨 → 페이지와 `Code.gs`의 가격이 다른 상태입니다. 숫자를 맞춘 뒤 스크립트를 새 버전으로 배포합니다.
- 시험 주문이 장부 판매에 잡힘 → 그 행의 상태를 `취소`로 바꾸거나 행을 지운 뒤 장부를 새로고침합니다.
