# 중고거래 장부

깃허브 페이지의 화면과, 구글 시트 `중고거래 장부 - Google Sheets 이전`에 붙이는 Apps Script 웹 앱입니다. 비밀번호는 페이지 소스에 없고, 스크립트 속성에만 있습니다. 맞는 비밀번호가 아니면 목록을 읽거나 고칠 수 없습니다.

화면 주소: https://for1916.github.io/1916/Trade_DB/

## 파일

| 파일 | 역할 |
| --- | --- |
| `index.html` | 장부 화면. 비밀번호는 이 탭의 `sessionStorage` 에만 두고, 요청마다 본문에 실어 보냅니다. |
| `apps-script/Code.gs` | 시트에 붙여 넣을 스크립트. 헤더 이름으로 열을 찾고, 기존 행은 초기 설정에서 바꾸지 않습니다. |

## 적용 순서

개발 도구는 필요 없습니다. **페이지를 먼저 반영하면** 옛 스크립트가 `action: "list"` 요청을 어떻게 받을지 알 수 없습니다. 아래 1–4를 끝낸 뒤에 이 폴더의 `index.html` 이 깃허브 페이지에 올라가게 하세요.

### 1. 옛 스크립트를 복사해 두기

이 저장소에는 지금 돌아가는 Apps Script 원문이 없습니다. 아래 코드는 페이지가 주고받는 모양으로 다시 만든 것입니다.

1. 구글 시트 **중고거래 장부 - Google Sheets 이전** 을 엽니다.
2. **확장 프로그램 → Apps Script** 를 엽니다.
3. 편집기에 있는 코드를 전부 복사해 컴퓨터에 텍스트로 저장합니다.
4. 시트 파일도 **파일 → 다운로드** 로 복사해 둡니다.

날짜가 이상하면 **배포 → 배포 관리** 에서 이전 버전을 다시 고르면 옛 동작으로 돌아갑니다. 그 전에 화면에서 저장을 누르지 마세요.

### 2. 새 코드 붙여 넣기

1. Apps Script 편집기의 내용을 모두 지우고, `apps-script/Code.gs` **전체**를 붙여 넣습니다.
2. 저장합니다.
3. **프로젝트 설정**에서 런타임이 **Chrome V8** 인지만 확인합니다. **시간대는 바꾸지 마세요.** 지금 구매일은 `…T07:00:00.000Z` 또는 `…T08:00:00.000Z` 로 나가고, 화면은 앞 10글자만 씁니다. 시간대를 바꾸면 그 날짜가 하루 밀릴 수 있습니다.

### 3. 비밀번호 저장

페이지에 적혀 있던 값은 소스와 깃 기록에 이미 남아 있습니다. 같은 값을 다시 써도 동작은 하지만, 새로 정하는 편이 안전합니다. 화면 입력칸은 20자까지입니다.

1. 시트 탭으로 돌아가 **새로고침**합니다.
2. 메뉴 **중고거래 장부 → 초기 설정** 을 누릅니다.
3. 비밀번호를 입력합니다. 4자 이상 20자 이하. 이미 저장돼 있으면 비워 두고 확인을 눌러도 됩니다.
4. 권한을 물으면 본인 계정을 고르고 허용합니다.

메뉴가 없으면 편집기에서 함수 **setup** 을 실행합니다. 편집기에서는 비밀번호 창이 안 뜰 수 있습니다. 그때는 **프로젝트 설정 → 스크립트 속성** 에 속성을 `TRADE_DB_PASSWORD`, 값을 비밀번호로 넣습니다. 코드에는 적지 않습니다.

초기 설정은 시트를 찾아 헤더만 확인합니다. 행을 지우거나 덮어쓰지 않습니다. **중고거래 장부 → 시트 점검** 에 `비밀번호: 설정됨` 과 시트 이름이 보이면 됩니다.

### 4. 같은 주소로 새 버전 배포

1. Apps Script **배포 → 배포 관리**
2. 지금 페이지가 쓰는 배포의 연필 아이콘
3. 버전: **새 버전**
4. 실행 계정: **나**, 액세스 권한: **모든 사용자** (영문은 Anyone). 구글 로그인을 요구하는 항목이 아닙니다. 비밀번호 검사가 접근을 막습니다.
5. **배포**

주소는 그대로입니다.

```text
https://script.google.com/macros/s/AKfycbwv9b613EfnpLSqtV6QnIq4tpuMkaPdLKsaF1UzDzZHjj93vUgVxQEnjNH6Hm5LiJu7/exec
```

배포를 새로 만들어 주소가 바뀌면 `index.html` 의 `SCRIPT_URL` 만 새 `/exec` 주소로 바꿉니다. `/dev` 주소는 쓰지 않습니다.

이 버전부터 주소만 열면 목록이 나오지 않습니다. `비밀번호가 필요합니다.` 만 나오면 막힌 것입니다.

### 5. 화면 확인

페이지가 반영된 뒤 https://for1916.github.io/1916/Trade_DB/ 를 엽니다.

1. 비밀번호 없이 목록이 보이지 않는지 확인합니다.
2. 비밀번호를 입력합니다. 같은 탭에서 새로고침하면 1시간 동안은 다시 묻지 않습니다. 탭을 닫으면 다시 묻습니다. 1시간이 지나면 예전과 같이 자동으로 잠깁니다.
3. **저장하기 전에** 목록의 구매일·판매일이 시트의 그 칸과 같은 날인지 봅니다. 하루 다르면 저장하지 말고 배포를 이전 버전으로 되돌린 뒤, 시간대를 되돌리고 다시 배포합니다.

잠금 화면의 힌트 칸(`pw-hint`)은 비어 있어서 보이지 않습니다. 문구를 넣으면 비밀번호 아래에 나옵니다. 힌트에 비밀번호 전체를 적지 마세요.

## 화면이 기대하는 데이터

페이지는 각 행에서 `id`, `buy_date`, `category`, `item_name`, `buy_type`, `buy_platform`, `buy_price`, `sell_date`, `sell_platform`, `sell_price`, `status`, `memo` 를 씁니다. `created_at` 과 `updated_at` 이 있으면 그대로 두고, 새 행과 수정한 행의 `updated_at` 만 바꿉니다. 새 행의 `id` 는 UUID 입니다. 예전 정수 id 는 바꾸지 않습니다.

빈 금액·빈 날짜는 칸을 비웁니다. 예전에 글자 `null` 로 들어가 있는 칸은 그 행을 저장하기 전까지 그대로 둡니다. 읽어 올 때만 빈 값으로 봅니다.

## 잘 안 될 때

- 비밀번호가 맞는데 `비밀번호가 아직 설정되지 않았습니다` → 스크립트 속성 이름이 정확히 `TRADE_DB_PASSWORD` 인지 확인하고, 웹 앱을 **새 버전**으로 다시 배포합니다.
- `거래 시트를 찾지 못했습니다` → 헤더 행에 `id`, `item_name`, `buy_date` (또는 `아이디`, `품목명`, `구매일`) 가 있는지 봅니다. 초기 설정은 이 경우에도 행을 고치지 않습니다. 시트 이름을 `jonggo_trades` 로 두면 같은 헤더가 여러 탭에 있어도 그 탭을 고릅니다.
- 목록이 비어 있거나 옛 스크립트와 같음 → `Code.gs` 를 다시 붙여 넣고 저장한 뒤 **새 버전**으로 배포합니다. 주소가 그대로면 `SCRIPT_URL` 은 바꾸지 않습니다.
- 날짜가 하루 다름 → 저장하지 말고 배포 관리에서 이전 버전을 배포합니다. 시트 시간대와 스크립트 시간대를 원래대로 둡니다.

## 확인하지 못한 것

옛 스크립트 원문이 계정 안에만 있어서, 배포 전에 동작까지 맞추지는 못했습니다. 읽기는 비밀번호 없이 열려 있어서 응답 모양만 봤고, 거래 내용은 저장하지 않았습니다. 쓰기는 시트를 건드리지 않으려고 호출하지 않았습니다.

- 성공한 읽기 응답은 `{ "data": [ ... ], "error": null }` 입니다. 행 키는 `id`, `buy_date`, `category`, `item_name`, `buy_type`, `buy_platform`, `buy_price`, `sell_date`, `sell_platform`, `sell_price`, `status`, `memo`, `created_at`, `updated_at` 입니다.
- `id` 는 1–62 정수이거나, 그 뒤에 추가된 행은 UUID 문자열입니다. 페이지의 추가·수정·삭제는 `insert` / `update` / `delete` 입니다. 성공 여부는 `error` 만 봅니다. 저장이 성공했을 때 옛 스크립트가 `data` 에 무엇을 넣었는지는 모릅니다.
- 시트 탭 이름은 응답에 없습니다. 헤더가 영문이거나 위 한글 이름이면 찾습니다. 둘 다 아니면 데이터를 바꾸지 않고 오류를 냅니다.
- 구매일·판매일의 `T07:00` / `T08:00` 은 미국 태평양 시간 자정과 맞습니다. 시트에 그 시각이 들어 있는 이유(시간대 또는 저장 방식)는 원문 없이 확정하지 못했습니다.
- 삭제는 그 행 전체를 지웁니다. 이 스크립트가 읽지 않는 열이 같은 행에 있으면 그 칸도 함께 사라집니다.
- 수식이 들어 있는 칸은, 그 행을 화면에서 저장할 때 값으로 덮일 수 있습니다.
- `created_at` 일부는 `2026-07-05 13:14:29.12392+00` 같은 예전 문자열이고, 나중에 만든 행은 ISO 문자열입니다. 있는 문자열은 그대로 두고, 새로 쓸 때만 ISO 문자열을 넣습니다.
