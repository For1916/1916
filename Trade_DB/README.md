# 중고거래 장부

깃허브 페이지의 화면과, 독립 Apps Script 웹 앱입니다. 스크립트는 시트에 묶여 있지 않고, 스프레드시트 `1IdfcAJQj1O9IgxxKUa4J-_hMSR-A6Vp-kSONFg78FRQ` 의 탭 `jonggo_trades` 를 엽니다. 비밀번호는 페이지 소스에 없고, 스크립트 속성 `TRADE_DB_PASSWORD` 에만 있습니다.

화면 주소: https://for1916.github.io/1916/Trade_DB/

## 파일

| 파일 | 역할 |
| --- | --- |
| `index.html` | 장부 화면. 비밀번호는 이 탭의 `sessionStorage` 에만 두고, 요청마다 POST 본문에 넣습니다. |
| `apps-script/Code.gs` | 독립 프로젝트에 붙여 넣을 스크립트. 예전과 같은 칸에 같은 방식으로 저장합니다. |

읽기는 `POST {action:"list", password}`. 추가는 `insert`, 수정은 `update`, 삭제는 `delete` 입니다. `GET` 은 행을 돌려주지 않습니다.

## 적용 순서

이 페이지가 깃허브에 올라가기 **전에** 스크립트를 새 버전으로 배포하세요. 배포 전에는 주소만 열면 목록이 나옵니다. 배포 후, 페이지가 반영되기 전에는 옛 화면의 읽기와 저장이 멈춥니다.

### 1. 독립 프로젝트를 연다

시트 메뉴 **확장 프로그램 → Apps Script** 가 아닙니다. 그 메뉴는 시트에 묶인 다른 프로젝트를 엽니다.

1. https://script.google.com 을 엽니다.
2. 지금 웹 앱을 배포한 프로젝트를 엽니다. **배포 → 배포 관리** 에 아래 주소가 있는 프로젝트입니다.

```text
https://script.google.com/macros/s/AKfycbwv9b613EfnpLSqtV6QnIq4tpuMkaPdLKsaF1UzDzZHjj93vUgVxQEnjNH6Hm5LiJu7/exec
```

3. 편집기에 있는 코드를 복사해 컴퓨터에 저장해 둡니다. 시트도 **파일 → 다운로드** 로 복사해 두면 더 안전합니다.

### 2. 코드를 바꾼다

1. 그 프로젝트의 `Code.gs` 를 모두 지우고, 이 폴더의 `apps-script/Code.gs` **전체**를 붙여 넣습니다.
2. 저장합니다.
3. 런타임은 **Chrome V8** 이어야 합니다. **스크립트 시간대는 바꾸지 마세요.** 날짜 형식인 칸은 그 시간대의 `yyyy-MM-dd` 로 나갑니다.

### 3. 비밀번호를 넣고 setup 을 실행한다

페이지에 적혀 있던 값은 소스와 깃 기록에 남아 있습니다. 새로 정하세요. 화면에서는 4자 이상 20자까지 입력됩니다. 코드 파일에는 적지 않습니다.

1. **프로젝트 설정 → 스크립트 속성 → 스크립트 속성 추가**
2. 속성: `TRADE_DB_PASSWORD`
3. 값: 비밀번호
4. 저장한 뒤 편집기로 돌아갑니다.
5. 함수 목록에서 **setup** 을 고르고 실행합니다.
6. 권한을 물으면 본인 계정을 허용합니다. 이 프로젝트는 시트를 ID로 엽니다.
7. 실행 로그에 `비밀번호: 설정됨`, `탭: jonggo_trades` 가 보이면 됩니다. `setup` 은 셀을 바꾸지 않습니다.

로그에 `비밀번호: 없음` 이면 속성 이름을 확인한 뒤 `setup` 을 다시 실행합니다.

### 4. 같은 주소로 새 버전을 배포한다

1. **배포 → 배포 관리**
2. 위 `/exec` 주소가 있는 배포의 연필
3. 버전: **새 버전**
4. 실행 계정: **나**, 액세스 권한: **모든 사용자** (영문은 Anyone)
5. **배포**

주소는 그대로입니다. 배포를 새로 만들면 주소가 바뀌므로, 그때만 `index.html` 의 `SCRIPT_URL` 을 새 `/exec` 주소로 바꿉니다. `/dev` 는 쓰지 않습니다.

이 버전부터 주소만 열면 `비밀번호가 필요합니다.` 만 나오고 목록은 나오지 않습니다.

### 5. 화면을 확인한다

페이지가 반영된 뒤 https://for1916.github.io/1916/Trade_DB/ 를 엽니다.

1. 비밀번호 없이 목록이 보이지 않는지 확인합니다.
2. 비밀번호를 입력합니다. 같은 탭에서 새로고침하면 1시간 동안은 다시 묻지 않습니다. 탭을 닫으면 다시 묻습니다. 1시간이 지나면 자동으로 잠깁니다.
3. 구매일·판매일이 시트의 그 칸과 같은 날인지 봅니다.

잠금 화면의 힌트 칸(`pw-hint`)은 비어 있어서 보이지 않습니다. 문구를 넣으면 비밀번호 아래에 나옵니다. 힌트에 비밀번호 전체를 적지 마세요.

## 저장 방식

예전 스크립트와 같습니다.

- 헤더는 `id`, `buy_date`, `category`, `item_name`, `buy_type`, `buy_platform`, `buy_price`, `sell_date`, `sell_platform`, `sell_price`, `status`, `memo`, `created_at`, `updated_at` 입니다.
- 날짜 값은 스크립트 시간대의 `yyyy-MM-dd` 로 나갑니다. 글자로 들어 있는 칸은 그 글자 그대로 나갑니다. 페이지는 앞 10글자를 씁니다.
- 추가는 UUID 를 `id` 에 넣고, `created_at` 과 `updated_at` 에 ISO 시각을 넣습니다. 나머지 칸은 요청의 값이고, 비어 있으면 빈 칸입니다.
- 수정은 `id` 와 `created_at` 을 그대로 두고 `updated_at` 만 새 시각으로 바꿉니다. 다른 칸은 요청에 있는 값으로 덮어씁니다.
- 삭제는 그 행을 지웁니다.
- 응답은 `{data, error}` 입니다.

탭이 없거나 완전히 비어 있을 때만, 비밀번호가 맞은 읽기·저장이 탭과 헤더 행을 만듭니다. 데이터가 있는 지금 시트에서는 그렇게 하지 않습니다. `setup` 은 어느 경우에도 셀을 바꾸지 않습니다.

## 잘 안 될 때

- `비밀번호가 아직 설정되지 않았습니다` → 속성 이름이 `TRADE_DB_PASSWORD` 인지 확인하고, 웹 앱을 **새 버전**으로 다시 배포합니다.
- 목록이 옛 스크립트와 같음 → 독립 프로젝트의 코드를 바꿨는지, **배포 관리**에서 새 버전을 배포했는지 확인합니다. 시트에 묶인 스크립트만 고치면 이 주소는 바뀌지 않습니다.
- `Record not found` → 그 `id` 행이 없습니다. 새로고침 후 다시 저장합니다.
